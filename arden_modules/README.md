# Arden Modules — самодостаточные сигналы (Модуль 1 + Модуль 2)

Движок торговых сигналов по методу Романа Арденского (SMC/ICT), собранный в один файл.
Работает от одного 1-минутного CSV, без остального проекта ASVK и без тяжёлых данных.

> Читаешь это как другой Claude/агент? Начни с **STRATEGY.md** — там логика стратегии.
> Здесь — как запустить и что на выходе.

## Состав папки
```
arden_modules/
  arden_signals_v2.py — движок v2 (РЕКОМЕНДУЕТСЯ): грейд по СИЛЕ факторов
  arden_signals.py    — движок v1: грейд по ЧИСЛУ факторов (для сравнения)
  STRATEGY.md         — что это за стратегия, как рождается сигнал, результаты, слабые места
  README.md           — этот файл (запуск)
  requirements.txt    — зависимости
```
Больше ничего не нужно, кроме CSV со свечами. Оба движка самодостаточны и взаимозаменяемы
по CLI; **v2 точнее** — используй его.

## v1 vs v2 (что изменилось)
v1 грейдил сигнал по ЧИСЛУ совпавших факторов. Но стратификация показала: 2 из 5 OHLC-факторов
(ext5, тело/фитиль) — почти шум (~42-44% WR), и `conf>=3` ими забивался → средний слой всего ~60%.
**v2 ранжирует факторы по реальной силе** и берёт силу сильнейшего присутствующего:

| сила | фактор | ~WR | v2-tier |
|------|--------|-----|---------|
| 5 | CHoCH (слом структуры) | 90-98% | `premium` |
| 4 | money_hands (объём+поглощение) | 75-83% | **`strong` ← production** |
| 3 | rsi_div (дивергенция) | ~66% | `wide` (опция) |
| 2 | bos (sweep+rejection) | ~58% | — |
| 1 | ext5 / тело-фитиль | 42-44% | шум, отбрасывается |

Итог: v2-`strong` (CHoCH ∣ money_hands) = **75-83% WR при ~2.7x больше сигналов**, чем один premium —
тогда как v1-`setup` на тех же данных был ~60%. Это перенос находки «возврат сильных сигналов
без разбавления слабыми» на самодостаточный OHLC-движок.

## Что это
- **Модуль 1** = движок на таймфрейме **12h**.
- **Модуль 2** = тот же движок на **2h / 3h / 4h / 6h**.
Один и тот же код, разный `--tf`.

## Данные
CSV Binance-формата, колонки: `open_time` (ISO8601 UTC), `open, high, low, close, volume`.
Файлы вида `BTCUSDT_1m.csv`, `ETHUSDT_1m.csv`, `SOLUSDT_1m.csv`. Данных в этой папке НЕТ —
путь к CSV передаётся аргументом `--csv`.

## Запуск (v2 — рекомендуется)
```bash
pip install -r requirements.txt

# Модуль 1 (12h), с живым вердиктом «сейчас лонг/шорт»:
python arden_signals_v2.py --csv /path/BTCUSDT_1m.csv --tf 12h --name BTC --live

# Модуль 2 (например 4h):
python arden_signals_v2.py --csv /path/SOLUSDT_1m.csv --tf 4h --name SOL --live

# сохранить все сигналы в parquet:
python arden_signals_v2.py --csv /path/ETHUSDT_1m.csv --tf 12h --save eth_12h.parquet
```
(v1 запускается так же: `python arden_signals.py ...` — те же аргументы.)

## Что на выходе
Печатает WR по уровням + грейдам и живой вердикт. Пример (BTC 12h):
```
  фрактал (база)   n= 4310  WR= 41.7%
  setup (CHoCH∪≥3) n= 1521  WR= 61.2%
  PREMIUM (CHoCH)  n=   66  WR= 90.9%  ← основной сигнал
    грейд 5 PREMIUM  n=   66  WR= 90.9%
  вердикт: СЕЙЧАС ▲ LONG  грейд 3/5 HIGH (2026-07-27 15:00 MSK, 1 бар назад)
```

## Колонки в parquet (при `--save`)
`ts, bar, direction(long/short), confirmable, confirmed, a2, a4, bos, choch, rsi_div,
money_hands, confluence(0..5), grade(1..5), premium(bool), setup(bool)`.

- **direction** — long / short.
- **confirmed** — исход: разворот устоял 2 бара (метрика WR, БЕЗ tp/sl).
- **premium** — сильный сигнал (слом структуры CHoCH), ~86–96% WR.
- **setup** — общий поток (CHoCH или ≥3 совпавших фактора).
- **grade 1..5** — уверенность (чем больше факторов, тем выше). Читать от 3 и выше.

## Проверенные результаты (BTC/ETH/SOL, 2020 → 2026-07)
| ТФ | PREMIUM (CHoCH) WR | сигналов PREMIUM/год |
|----|--------------------|----------------------|
| 12h | 90–98% | ~4 |
| 6h  | 88–93% | ~30 |
| 4h  | 86–93% | ~42 |
| 3h  | 86–89% | ~48 |
| 2h  | 87–92% | ~60 |

**Как читать сигнал:** свежесть → направление → грейд. Действовать на свежие
(«НА ЭТОЙ СВЕЧЕ»), приоритет — PREMIUM (грейд 5). FLAT — норма, большую часть времени сигнала нет.

## Важные оговорки (честно)
1. `confirmed` = «разворот устоял 2 бара», НЕ прибыль по цели. TP/SL здесь не считаются.
2. Средний слой (`setup`/грейд 3–4) на этом лёгком OHLC-ядре слабее (~55–70%). Рабочая
   ценность — в PREMIUM (CHoCH). Полный сильный «setup 79–86%» из большого проекта ASVK
   требует тяжёлых блоков (e12d/s7d) и в эту самодостаточную папку не входит.
3. CHoCH и `confirmed` частично коррелируют по построению — часть высокого WR механически
   ожидаема, но паттерн причинный и торгуемый.
