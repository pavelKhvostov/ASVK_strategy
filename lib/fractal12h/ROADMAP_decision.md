# Слой решения ASVK + дорожная карта модулей (метод Арденского → ASVK)

Цель: сигналы с **WR > 75%** в логике ASVK «фрактал сформировался/нет» (без tp/sl).
База: `fractal12h` = автоматизация Power of Three. A1-пивот = кандидат; `*_hit` = подтверждение;
`confirmed` (Williams n=2) = исход «фрактал устоял».

## Диагноз
`basket` = **OR(B1..B9)** → BTC WR ~74.2%. Отдельные сильные блоки выше:
B4 84.0 · B9 83.9 · B5 81.9 · B8 80.8 · B2 79.9 · B1 77.7 · B3 75.7. OR разбавляет их
слабыми одиночными срабатываниями. Методичка Арденского предписывает лечение: сетап = **слияние**
нескольких обязательных факторов (усиление PoT: 3 фактора → 90%; магия зон: H1+H4+D1 → 70.5%).

## Шаг 1 — ГОТОВ: `decision.py`
Слой решения поверх корзины. Роли блоков (анатомия сетапа Арденского):
- ЗОНА = b1(FVG) | b2(OB) · ЛИКВИДНОСТЬ = b3 · ПОДТВЕРЖДЕНИЕ = b4|b5|b8|b9.
- `decision_setup` = ЗОНА & ПОДТВЕРЖДЕНИЕ (production-сигнал) · `decision_pot` = ЗОНА & ЛИКВ & ПОДТВ.
- Плюс простые пороги `decision_k2/k3` (confluence ≥ 2/3) для сравнения.
Встроен в `run_fractal12h.py` после basket; пишет `decision_hits_{SYM}_*.parquet`.

**Запуск (на реальном ASVK, где python с pandas):**
```
python lib/fractal12h/run_fractal12h.py --symbol BTC --start 2020-01-01 --end 2026-07-29
# или только слой решения поверх готового basket:
python lib/fractal12h/decision.py --symbol BTC --start 2020-01-01 --end 2026-07-29
```
Прогнать по BTC/ETH/SOL, сравнить tiers, взять минимальный tier с WR>75% при достаточном n.

### Результат шага 1 (прогон 2020-01-01 → 2026-07-29)
| символ | A1 base | OR-basket | **decision_setup** | conf≥3 | pot |
|--------|--------|-----------|--------------------|--------|-----|
| BTC | 41.4% | 74.2% (746) | **86.5% (192)** | 86.6% (232) | 84.7% (111) |
| ETH | 41.1% | 70.7% (776) | **83.0% (212)** | 83.1% (213) | 86.0% (107) |
| SOL | 39.8% | 69.6% (658) | **79.0% (163)** | 82.8% (170) | 83.0% (89) |
Цель WR>75% достигнута на всех символах, без новых детекторов. +12/+12/+9 п.п. над OR.

## Шаг 2 — ГОТОВ: `b_structure.py` (BOS / CHoCH / sweep)
Закрыл пробел: детектора структуры в ASVK не было. Причинно на 12h, поверх A1-пивотов.
Sub-условия: `bstruct_sweep` (вынос swing-уровня), `bstruct_bos` (sweep+rejection close),
`bstruct_choch` (закрытие пробило противоположный swing = разворот). Свёрнут в `decision.py`.

**Результат: новый премиум-tier `decision_choch` (зона&подтв&CHoCH):**
| символ | decision_choch WR | n (6.5 лет) |
|--------|-------------------|-------------|
| BTC | **96.4%** | 28 |
| ETH | **96.6%** | 29 |
| SOL | **95.7%** | 23 |
CHoCH — редкий, ~4 сигнала/год, но почти без промахов. Как бустер к `setup` даёт мало
(setup уже ловит большинство), ценен как отдельный ultra-high-conviction класс.
`bstruct_bos` один = 58% (умеренно), `bstruct_sweep` один = 42% (≈baseline, не берём).

### Рекомендуемая ИЕРАРХИЯ сигналов (= «три зоны входа» Арденского Zone C/D/E)
- **Tier A · премиум ~95%+** — `decision_choch` (редко): максимальная уверенность.
- **Tier B · сильный 79–86%** — `decision_setup` (зона&подтв): основной production-поток.
- **Tier C · для слабого символа** — `conf≥3` / `pot` подтягивают SOL к 83%.

## Шаг 3 — ГОТОВ: `b6_divergence.py` (RSI, канон-блок B6)
RSI(14) Wilder на 12h, регулярная дивергенция vs предыдущий фрактал. Причинно.
`b6c1` (дивергенция) один = 67.8/65.1/65.5% WR (крепкий confirm). `b6c2` (OB/OS) = 37/31/33% —
хуже baseline (в крипте перекупленность держится в тренде), в production НЕ берём.
Свёрнут в decision. Эффект: `setup_x` (+RSI в confirm) = больше сигналов, WR −1.5..2.7пп;
`decision_div` (дивергенция доп.фактором) = **ETH 89.0%** (+6пп), BTC/SOL нейтрально.
Итог: полезный опциональный диал, крупный выигрыш не даёт, SOL не поднимает.

## Шаг 4 — ПРОВЕРЕН, В PRODUCTION НЕ ВЗЯТ: `b_ote.py` (Premium/Discount)
Направленный фильтр Арденского (шорт из Premium, лонг из Discount) по дилинг-рейнджу
(rolling 60×12h = 30д). Результат: `ote_side` = 39.2/38.3/37.2% WR — **ниже baseline (41%)**.
Причина: фрактал-хай по построению уже наверху локального диапазона; «премиум»-пивоты часто
в сильном аптренде, который не разворачивается. Концепт P/D работает для входов ПОСЛЕ BOS,
а не для сырых разворотных пивотов. Модуль оставлен для research, в decision НЕ свёрнут.
→ Честный отрицательный результат: не каждый модуль помогает (петля поиска слабых мест работает).

## Шаг 5 — ГОТОВ: `b7_money_hands.py` (канон-блок B7)
Умные деньги = климакс-объём (vol ≥ 1.5× среднего за 10д) + поглощение (закрытие в сторону
разворота). Причинно. `b7c1` (production) = 82.4/74.8/73.8% WR — крепкий confirm. `b7c2`
(экстрим-объём без rejection) = 49-56%, отброшен. В базовый confirm НЕ включён (роняет SOL до
75.9%, тонкий запас); работает как расширитель охвата (`decision_setup_w`) и доп.фактор
(`decision_mh` = зона&подтв&money = **89.0/88.4/81.7%** — выше базового setup!).

## Шаг 6 — ПРОВЕРЕН, В PRODUCTION НЕ ВЗЯТ: `sd_filter.py` (режим SD)
SD = размах бара пивота / ATR14. `sd_ge1` (сильный импульс) = 45/44/42% WR ≈ baseline. Как
b_ote — режим силы движения не предсказывает разворот. Оставлен для research, в decision не свёрнут.

## Шаг 7 — ГОТОВ: `verdict.py` — живой вердикт «сейчас LONG/SHORT/FLAT»
Отвечает на вопрос в стиле ASVK: на текущей закрытой 12h-свече система думает лонг или шорт.
Берёт самый свежий активный сигнал (≤4 баров) по иерархии tier'ов A(CHoCH)>B(setup)>C(pot),
печатает направление + свежесть («НА ЭТОЙ СВЕЧЕ ✓» при age=0) + JSON для TUI. Встроен в
run_fractal12h. Пример (данные до 2026-07-27 15:00 MSK): BTC FLAT, ETH FLAT, SOL ▼SHORT на этой свече.

## Итог 7 модулей
| модуль | эффект | в production |
|--------|--------|--------------|
| decision (confluence) | **+9..12пп над OR, 79-86% WR** | ✅ да |
| b_structure (CHoCH) | **премиум-tier 95-96%** | ✅ да |
| b7_money_hands | **decision_mh 89/88/82%** (доп.фактор) | ✅ да (доп/шире) |
| b6_divergence (RSI) | ETH-div 89%, иначе нейтрально | ◐ опционально |
| verdict | живой LONG/SHORT/FLAT на текущей свече | ✅ да |
| b_ote (Premium/Discount) | ниже baseline | ✗ нет |
| sd_filter (режим SD) | ≈baseline | ✗ нет |

Крупные выигрыши: **confluence + CHoCH + money-hands**. Финальный production-стек:
Tier A `decision_choch` (~95%) · `decision_mh` (89/88/82) · Tier B `decision_setup`/`decision_hit`
(79-86%) · Tier C `pot`/`conf≥3` (для SOL ~83%) · шире `decision_setup_w`. Живой вердикт → `verdict.py`.
Отрицательные (не для разворотных пивотов): b_ote, sd_filter.

## Порядок по приоритету (impact × дешевизна)
1. **decision.py** (готов) → прогнать, замерить WR по 3 символам.
2. **b_structure.py** (BOS/CHoCH) — самый большой пробел, ядро метода.
3. **b6_divergence.py** — дёшево, зарезервирован.
4. **b_ote.py** — Premium/Discount гейт.

6. **session_filter.py** — отдельно, на каскады Liq_OB/FVG_OB.

## Слабые места, которые ищем в прогоне (шаг 2+)
- Какой tier (`setup` / `pot` / `k3`) первым даёт **WR>75% при n достаточном** для торговли.
- **Per-symbol провал:** BTC baseline 74%, но ETH/SOL могут отличаться — проверить, не падает ли WR.
- **Selectivity:** сколько сигналов остаётся после AND — не слишком ли мало.
- **Метрика `confirmed`** = Williams-n2 (2 бара вперёд) = «фрактал устоял», это НЕ PnL по цели.
  Честный предел: WR по confirmed ≠ WR по достижению TP. Пока (по ТЗ) без tp/sl — принимаем как есть,
  позже отдельной колонкой добавить outcome по проекции цели.
- **Null-баг после outer-merge** (критика ASVK): под-условия bXcY бывают NaN → `bool(nan)=True`.
  `decision.py` использует только top-level `b*_hit` (basket их fillna(False)) — не задет, но при
  добавлении новых блоков следить за fillna.
